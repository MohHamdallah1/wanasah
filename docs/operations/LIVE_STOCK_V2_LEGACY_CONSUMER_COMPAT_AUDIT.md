## Authority, scope and interpretation

- The binding decision in merged [#687](https://github.com/MohHamdallah1/wanasah/pull/687), [#693](https://github.com/MohHamdallah1/wanasah/pull/693), [#695](https://github.com/MohHamdallah1/wanasah/pull/695), [#694](https://github.com/MohHamdallah1/wanasah/pull/694), issue [#692](https://github.com/MohHamdallah1/wanasah/issues/692) and `docs/operations/LIVE_STOCK_V1_R3_PHYSICAL_LOCATION_TRUTH.md`: **`InventoryBalance` at the actual `InventoryLocation` is the physical source of truth**. Route source/status/history never determines quantity location.
- For **`GET /warehouse/inventory/cursor`** only, `on_hand_quantity` and alias `total_quantity` mean selected-Warehouse physical total across statuses; `total_quantity_scope=WAREHOUSE_PHYSICAL`. `available_for_sale_quantity` and alias `available_quantity` are sellable unreserved **Warehouse** base quantity; `blocked_quantity` is a backward-compatible Warehouse-derived ineligible partition (not all Vehicles; not equivalent to only status `BLOCKED`). Vehicle disclosure `vehicle_quantity` separately sums readable VEHICLE locations; `vehicle_quantity_scope` is `COMPANY_WIDE`, `AUTHORIZED_LOCATIONS`, or `NO_ACCESS`; the last must be **null**, not zero. `has_vehicle` means positive custody in readable Vehicles even if not associated with selected Warehouse. `IN_TRANSIT` and `SCRAP` are never Warehouse quantities. `vehicle_packs` and `has_vehicle_presence` in persisted Warehouse projection are storage compatibility only, zero/false in v2.
- **Different endpoints may use the same generic field name with intentionally different meaning**: e.g. `total_quantity` for a whole-product quality preview includes all physical locations; transfers have transfer-line totals, opening valuation has financial quantities, and inbound adjustments have a selected Warehouse adjustment quantity. Never globally reinterpret these as Live Stock page fields.
- Evidence below points to source **at exact base SHA** using `path:Lx-Ly` (1-based). Existing tests are cited as previously verified/coverage, not as newly executed in this audit. Source trace is not runtime reproduction.

## Investigation and disposition

1. **Confirmed current-runtime P0/P1 v2 compatibility defects: none found in traced code**. This is a *source-based negative finding*, not a blanket PASS, deployment release, or proof that every downstream integration was executed. In particular, the actual SQL-authoritative `vehicle_quantity` remains separate from Warehouse, no active Live Stock client adds Vehicle to Warehouse `total_quantity`, and UI's `NO_ACCESS` path displays redaction instead of zero. Existing real [R3 physical-location PG16 acceptance](https://github.com/MohHamdallah1/wanasah/pull/687) and [Dashboard browser proof](https://github.com/MohHamdallah1/wanasah/pull/693) support specific contracts; they do not replace combined release acceptance.
2. **One confirmed stale non-production contract (P2):** `wa_backend/scripts/gate_live_stock_filter_contract.py:L68-L79` expects `projection.vehicle_packs` in the current `api/warehouse/live_stock.py`, but v2 correctly excludes it. The current `.github/workflows/live-stock-v1-r4-query-optimization.yml` lists that path as a trigger; it does **not** run the script as one of its job steps. Thus this is a **dormant/optional acceptance-script defect**, not an observed red exact-head CI run, and not evidence production quantity is wrong. Correct only under its own gate owner's approval; never weaken the v2 physical assertions.
3. **Limited sources view, not stock loss:** the batch action sources API returns only actionable physical WAREHOUSE/VEHICLE entries (`live_stock.py:L3208-L3223`), whereas the cross-location product quality preview includes `IN_TRANSIT` and `SCRAP`. Users must not take an action picker as a company-wide physical stock inventory. No proof of an incorrect on-screen grand total was found; label and broader consumer expectations need separate product-owner confirmation if expanded.
4. **Deployment and stale compatibility:** the preserved warm React memory cache is not a license to show verified quantities after a v1→v2 schema/semantic change. Production API must return 503 for v1 company or Warehouse summary; UI must retain admission and unverified/error banners. This audit did not rerun #700's isolated v1→v2 PostgreSQL proof or any operational browser acceptance.
5. **Regression protection already present:** `dashboard/src/pages/inventory/liveStock/contracts.ts:L344-L370` rejects missing/contradictory vehicle and total scopes; `test_live_stock_r4_negative_filter_contract.py` forbids `projection.vehicle_packs` and latest-Route attribution; `test_live_stock_r1_http_postgres.py:L109-L201` exercises bearer/RLS and live Vehicle grant revocation; `dashboard/e2e/live-stock-physical-custody.spec.ts:L11-L82` exercises real API, no-route load, COMPANY_WIDE/AUTHORIZED_LOCATIONS/NO_ACCESS and exact Warehouse totals. No new regression test added because no *unprotected current runtime* field-compatibility failure was isolated; adding a test of a dormant historical script would not prove an application fix.
