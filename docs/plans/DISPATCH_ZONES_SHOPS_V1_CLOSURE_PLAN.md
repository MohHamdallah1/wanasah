## 1. Architecture constitution — mandatory on every future PR

1. Follow `ARCHITECTURE.md` §§1–5, 12 and its mandatory decomposition discipline §§308–319 **exactly**; also `DRIVER_DISPATCH_MODULARIZATION_PLAN.md`, `DRIVER_DISPATCH_SEAM_INVENTORY.md`, `V1_SCOPE_FREEZE.md`, `.rules`, and `AGENTS.md`.
2. The system remains a single deployable modular monolith. No microservices, mass API renames, extra shared mutable authority, or a big-bang split during this page pass.
3. `wa_backend/api/dispatch.py` (~5,946 lines) and `wa_backend/api/driver.py` (~4,040 lines) are **shrinking legacy compatibility surfaces, NOT expansion points**. New business logic belongs under cohesive domain/application modules; if it depends on code trapped in a giant router, extract the **smallest cohesive existing seam** and preserve URLs, validation, transactions, locks, auth, response/retry and costing behavior. The touched legacy area must stay the same size or shrink in **business responsibility**. A new mega-file or god-function is forbidden. Do not physically split these large files now.
4. `dashboard/src/pages/DispatchBoard.tsx` (~2,085 lines) is likewise a shrinking composition shell, not the place for major new state/data/business logic. Build independently testable modules under `dashboard/src/features/dispatch/<responsibility>/`, reuse `dashboard/src/components/dispatch/` where appropriate, and keep read hooks, commands, contracts and presentation separate. No cosmetic broad rewrite.
5. Backend authority: canonical Backoffice capability + tenant + exact applicable location/route/vehicle; Field Representative is distinct. Inventory owns actual Warehouse/Vehicle custody, batch/FEFO/movements; Dispatch owns route/assignment/load orchestration; Pricing/Tax/Offers own publication/commercial rules; Finance/Costing owns financial value/COGS; no competing truth in UI or plan tables. A route status alone moves **zero stock**. Fail closed on permission revoke, ambiguous response or unknown custody.
6. Every PR must include an explicit file-ownership and module-boundary map. Cross-domain ownership decisions STOP and return to LEAD/owner; no agent may silently decide a new contract.

**Future target map (not a request to create all folders now):** `DRIVER_DISPATCH_MODULARIZATION_PLAN.md` §3 (thin `wa_backend/api/dispatch/{shop_zone,route_planning,route_inventory,route_lifecycle,settlement,shortages,read_models}` routers with application/domain ownership), `wa_backend/domains/dispatch/...`, and focused Dashboard dispatch feature modules.
