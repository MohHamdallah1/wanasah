المتبقي كاملًا:
إصلاح واجهة العروض بالكامل: المستخدم يختار المنتج المؤهل، المنتج/المنتجات المكافأة، ووحدة كل واحد بوضوح: حبة/كرتونة/أي UOM صالح، وكمية المكافأة لكل منتج. وتدعم بسهولة: اشترِ A وخذ A، اشترِ A وخذ B، وعدة مكافآت عند الحاجة. الـBackend يدعم uom_id + quantity_per_application حاليًا، لكن الواجهة لا ترسلهم بشكل صحيح.
إعادة تصميم تجربة إنشاء العروض لتكون مفهومة لغير التقني: بدل مصطلحات داخلية وحقول مبعثرة، Workflow خطوة بخطوة: نوع العرض → ماذا يشتري العميل → ماذا يحصل → الكمية والوحدة → من يشمله → المدة → مراجعة النتيجة → نشر. مع الحفاظ على كل مرونة المحرك.

إكمال كل أنواع العروض بدون استثناء: خصم نسبة، خصم ثابت، اشترِ X وخذ Y، بضاعة مجانية، شرائح كمية، Bundle. كل نوع له Form خاص واضح، Validation خاص، Preview حقيقي، UOM صحيح، وحدود تطبيق صحيحة. حاليًا بعض عقود الواجهة قديمة مقارنة بالـBackend.

إصلاح إدارة الضرائب وتجربتها: نخلي النظام مرن لأي دولة وشركة لكن المستخدم العادي ما يحتاج يفهم jurisdiction / reporting code / basis mode من أول شاشة. نستخدم إعداد موجّه، defaults مفهومة، Advanced options عند الحاجة، مع بقاء versioning/effectivity والحساب الصحيح كما هو. الواجهة الحالية ما زالت تقنية أكثر من اللازم.

إكمال Preview للعروض والضرائب بحيث يعرض للمستخدم بلغة تجارية مفهومة: قبل الخصم، العرض المطبق ولماذا، المكافأة ووحدتها، الضريبة ومكوناتها، والمبلغ النهائي. وليس مجرد IDs/Revisions.

إظهار تاريخ النسخ والنشر بشكل مفهوم: مسودة، بانتظار الموافقة، منشور، مستبدل، ملغي؛ مع تاريخ السريان ومن عدّل/نشر، بدون إجبار المستخدم على فهم تفاصيل الـrevision الداخلية.

إكمال Return reversal من Original Sale Line: أي مرتجع لازم يرتبط بالبيع الأصلي وبـsales revision/line الصحيحة ويعكس evidence الأصلية، لا يعيد حساب السعر أو العرض أو الضريبة من الوضع الحالي. هذه النقطة ليست منجزة بعد وهي شرط صريح بالخطة.

تدقيق Immutable Sales Evidence بالكامل بعد المرتجعات: السعر، الخصم، العرض، المكافأة، الضرائب، UOM، revisions، snapshots؛ البيع المنشور لا يتغير، والتصحيح/المرتجع يكون بعكس وتسجيل جديد فقط.
تنظيف عقود Legacy المتبقية بدون حذف عشوائي: لا Runtime consumer قديم للأسعار/العروض/الضرائب. Gate تاريخية مسموحة، والكود الميت لا يُحذف إلا بعد تدقيق وموافقتك.

تدقيق واجهات Commercial كاملة من ناحية سهولة الاستخدام: خصوصًا التسعير، الدفتر، العروض، الضرائب. المبدأ من الآن: الوضع العادي بسيط جدًا، والمرونة المتقدمة موجودة عند الحاجة. لا نخسر السرعة، ولا المرونة، ولا الجودة لصالح بعض.

اختبارات الواجهة فعلًا: TypeScript typecheck + build + tests + التأكد أن الـDashboard يرسل العقود الجديدة الصحيحة للـBackend، خصوصًا UOM والمكافآت.

اختبارات Backend/DB شاملة من جديد لكل Stage 6: offers بكل الأنواع، taxes، mixed UOM، reward inventory، corrections، returns، cross-tenant، idempotency، concurrency/locks، rollback، precision، immutable evidence، وعدم وجود N+1 أو dual authority.
