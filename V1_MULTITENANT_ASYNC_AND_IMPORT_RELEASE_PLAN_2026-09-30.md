## Non-negotiable architecture goal
- Different tenants must make sales, create invoices, update inventory and submit independent imports without globally serializing all work behind one bulk job.
- Acknowledging 1,000 simultaneous submissions is distinct from executing 1,000 database mutations in one instant. Define separate acceptance/queue-lag/completion and ordinary-business p95/p99 SLOs on representative production-sized hardware; do not promise zero latency effect or arbitrarily multiply workers.
- Preserve tenant RLS, Product/Variant identity, FIFO/MA financial records, immutable pricing history, audit/outbox, idempotency, worker crash semantics, barcodes and unique/exclusion constraints.
- Do not modify live indexes, delete import data, disable audit, or merge application code without independent code review and acceptance gates. One bounded change per branch.
- Owner decision (2026-09-30): ONLY correct, long-term, root-cause fixes are accepted. No temporary patch, superficial worker-count bump, silent deferral of safety issues or unverified performance claim. Prefer a harder superior design over an easier incomplete one, but do not rewrite proven-safe logic without evidence.
